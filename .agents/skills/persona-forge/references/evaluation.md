# 効き目の検証

書いただけのペルソナは、効いているか分からない。次のテストで測る。どのテストでも、**判定役は人格を読んでいない別のエージェント**（サブエージェント）にする。読んでいると判定が甘くなる。演じる役は、生成したサブエージェント定義（`persona-<slug>`）で立てる。

| テスト | 必須か | 測るもの |
|---|---|---|
| ルール遵守テスト | 必須 | ルールを守った出力が出るか |
| 仕込みテスト | 使い手で必須 | 使い手が、引っかかるべき所で引っかかるか |
| 見分けテスト | 推奨 | 人格なしの出力と違いが出るか |
| ペルソナ同士の見分けテスト | 同じ種類のペルソナが複数あるとき | 2 人の出力が見分けられるか |
| 設定削除テスト | 任意 | 個々の設定が出力を変えているか |

結果はすべて log.md に記録する（末尾の書式）。

---

## ルール遵守テスト（必須）

1. 用途に沿ったお題を 3 つ用意する。作り手なら作る役、使い手なら批評する役で、ペルソナに出力させる
2. 判定役に、ルール表と出力だけを渡す。人物像は渡さない。ルール表は lint に `--rules` を付けて出す（`node "<スキルのディレクトリ>/scripts/lint-persona.mts" --rules <ペルソナのディレクトリ>`）。由来・感性・記憶・心の声を除いた、ID と判断だけの表が出る
3. 判定役に、ルールごとに `○`（守れている）・`×`（破っている）・`該当なし` を、根拠の箇所つきで判定させる
4. 出力に添えられた根拠の ID と、判定役の判定を突き合わせる

合格の目安: 該当するルールの 9 割以上が `○`。`×` のルールは次のどれかに当たる。

- 判断が守れたか判定できない書き方になっている（判定役が `○` / `×` で迷った）→ 判断を具体的に書き直す
- 演じる側が読んでいない → 入口の「演じるときに読むファイル」と、そのファイルにルールがあるかを確かめる
- 他のルールとぶつかっている → 優先する側を translation.md に書く

## 仕込みテスト（使い手で必須）

1. 引っかかる瞬間（moments.md の `F`）と道のり（journeys.md の `J`）に反する箇所を、意図して 3 つ仕込んだ画面・操作の流れを用意する。HTML のプロトタイプか、手順を文章で書いたものでよい
2. 使い手のペルソナに、なぞる役でそれを進ませる
3. 判定役に、流れ、仕込みの一覧（どの手に何を仕込み、どの ID で引っかかるはずか）、ルール表（`--rules`）、演じた出力を渡し、仕込んだ箇所で引っかかり、正しい ID（または近い ID）を添えたかを判定させる。ルールの当てはめが過剰・誤りの箇所と、判定しにくいルールも挙げさせる

合格の目安: 3 箇所中 3 箇所で引っかかる。仕込んでいない所で引っかかった場合は、その指摘が人物の状況から妥当かを見る。妥当なら新しい `F` の候補として log.md に書く。

## 見分けテスト（推奨）

1. お題を 3 つ用意し、各お題について人格ありと人格なしで 1 つずつ出力を作る
2. 判定役に、順番を伏せて 2 つの出力を見せ、「片方は特定の人物の好みで作られている。どちらか」「その人物はどんな人か。根拠も」と聞く

合格の目安: 3 問中 3 問で当て、根拠がルール（translation・signatures など）の内容と一致する。当てたが根拠が設定と無関係なら、たまたまの差で当たっている。お題を増やして測り直す。

このテストで測れるのは「違うか」だけで、「良くなったか」は測れない。

## ペルソナ同士の見分けテスト

`personas/` に同じ種類のペルソナが複数あるときに行う。

1. 同じお題で 2 人に出力させる
2. 判定役に、2 人の入口の人物像の要約と 2 つの出力を見せ、どちらがどちらの出力かを当てさせる

当てられなければ、2 人は実質同じ人物である。統合するか、違いが出るルールを足す。

## 設定削除テスト（任意）

1. ID を 1 つ選び、translation.md から一時的に外す（ファイルは写しを使い、元を書き換えない）
2. 同じお題で出力を作り、外す前と比べる
3. 違いがなければ、その設定は飾り。判断を具体的に書き直すか、ID を外して素材に格下げする

## 操作の気持ちよさについて

操作の気持ちよさそのものは、エージェントには判定できない。スキルで確かめられるのは、ルールの遵守と、なぞって引っかかる箇所までである。本物の利用者で試した結果は、log.md に記録してルールを育てる材料にする。

## log.md の書式

```markdown
### 2026-01-01 ルール遵守テスト
- お題: 申請一覧 / 申請の入力 / 差し戻しの通知
- 結果: 該当 14 件中 13 件が ○
- × だったもの: T3（判定役の根拠: 色を 2 つの意味に使っている）
- 対応: T3 の判断を書き直した
```

採用・却下・批評を記録するときも同じ形で、見出しに `採用` `却下` `批評` などを書き、根拠の ID を必ず入れる。ルールを消したときは、その記録に `- 廃止: T3` の行を入れる。
