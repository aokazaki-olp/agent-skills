# サブエージェント定義の書き方

ペルソナごとに、入口を読ませるだけの薄い定義を `.claude/agents/persona-<slug>.md` に書く。雛形は `assets/templates/agent.md`。人格の中身は定義に書かず、`personas/<slug>/` だけを情報源にする。育てたときに二重管理にならないようにするため。

以下の仕様は Claude Code の subagents の文書（code.claude.com/docs/en/sub-agents、v2.1.289 時点）で確かめたもの。食い違いを見つけたら、文書の現行版で確かめ直す。

## 仕様

- 定義は YAML の frontmatter と、システムプロンプトになる Markdown の本文からなる。必須のキーは `name` と `description` だけ
- サブエージェントに渡るのは、本文（システムプロンプト）と、作業ディレクトリなどの基本的な環境情報だけ。Claude Code のシステムプロンプトも、呼び出した会話の文脈も渡らない
- サブエージェントは、メインの会話の作業ディレクトリで始まる
- `name` は一意の識別子で、`:` を含められない（含むと読み込まれない）。ファイル名と一致している必要はない
- 同じ `.claude/agents/` の中（サブフォルダを含む）で `name` が重なると、どちらが読まれるかは決まっていない
- `description` は、Claude がいつこのサブエージェントに任せるかの判断に使われる
- `tools` を省くと、サブエージェントが使えるツールをすべて引き継ぐ
- Claude Code は `.claude/agents/` を監視していて、追加・変更は数秒で反映される。ただし、セッションの開始時になかった `agents` ディレクトリに最初の定義を作ったときは、再起動が要る
- 次のファイルは、セッションに何も表示されずに読み飛ばされる: `name` がない、`---` がファイルの 1 行目にない、`name` が `-` で始まるか `:` を含む、`description` がない、YAML が読めない。理由はデバッグログ（`--debug` で起動）に出る

## 書き方

- `name`: `persona-<slug>`。書く前に `.claude/agents/` の下（サブフォルダを含む）に同じ `name` がないことを確かめる。既存のファイルは上書きしない
- `description`: 人物の 1 行の要約と役割を書き、**呼び出し側が名前で指名したときに使う**ことを明記する。ペルソナは、頼まれていない作業に自動で割り当てられると困るため
- `description` の値に半角の `: ` を含めない（含めるなら値全体を引用符で囲む）。YAML として読めなくなり、定義ごと読み飛ばされる
- `tools`: 書かない。役割（作る・なぞる・批評する）によって要るツールが違うため
- `model` などほかのキーは、ユーザーが求めたときだけ足す
- 本文: 最初に入口（`personas/<slug>/PERSONA.md`）を読み、その指示に従うことを書く。入口のパスはプロジェクトのルートからの相対パスで書き、作業ディレクトリがルートでなければ、リポジトリのルートを探して解決させる
- 本文に人物像・ルールを書かない

## 確かめ方

- 書いたら、検証のテストで実際に `persona-<slug>` を立てて確かめる（現行の `/agents` は一覧を出さない）
- 見えないときは、上の読み飛ばされる条件に当たっていないか、セッションの開始時に `.claude/agents/` があったかを確かめる
