# 使い手ペルソナの層の書き方

目次: ファイル構成 / 根拠の区別 / lint が検査する形 / §1 profile / §2 context / §3 translation / §4 journeys / §5 moments / §6 memories / §7 voice / §8 PERSONA.md

使い手のペルソナは、対象の層にとって迷わず気持ちいい操作を判断させるためのもの。作り手の好みではなく、使う状況と慣れから判断を導く。

## ファイル構成

| ファイル | 中身 | 演じるときに読む |
|---|---|---|
| `PERSONA.md` | 入口。人物像の要約、読むファイル、役割ごとの演じ方、出力の約束、自己批評 | ○ |
| `context.md` | 使う状況（場所・姿勢・ながら作業・急ぎ具合・頻度）と、状況の中での葛藤 | ○ |
| `translation.md` | 判断のルール表（`T`・`M`） | ○ |
| `journeys.md` | 目的を果たすまでの道のり（`J`） | ○ |
| `moments.md` | 気持ちいい瞬間（`G`）と引っかかる瞬間（`F`） | ○ |
| `voice.md` | 口調と、思考発話のサンプル | ○ |
| `profile.md` | 使っているアプリ・サービス・道具（固有名詞） | 設計の素材 |
| `memories.md` | 痛い目を見た経験と、そこから生まれた期待 | 設計の素材 |
| `research.md` | 調査の出典（`R`） | 設計の素材 |
| `log.md` | 採用・却下・批評・テストの記録 | 設計の素材 |

## 根拠の区別

profile.md と context.md の各項目（`- ` で始まる行）の末尾に、`〔出典: R1〕`・`〔推測: R2〕`・`〔指定〕`・`〔設計〕`・`〔仮〕` のどれかを付ける。意味と使い分けは作り手と同じ（`references/layers-maker.md` の「根拠の区別」）。使い手は想像で埋めると害が大きいので、苛立ちはできるだけ出典を付ける。状況（場所・姿勢）は統計が少ないので、当事者の発言から取り、取れなければ `〔仮〕` のまま残してユーザーに確かめる。ユーザーが一次データ（インタビュー、利用データ）を持っていれば、それを research.md に `種別: 一次データ` として載せて出典にする。

## lint が検査する形

表の列名、`###` の見出しの形（`### J1 …` など）、下の表に挙げた `##` の見出しを変えない。lint は次の形を前提に読む。profile.md と context.md の `##` の見出しは自由に変えてよい。表のセルに `|` を書くときは `\|` と書く。

| ファイル | 形 |
|---|---|
| `profile.md`・`context.md` | `- ` で始まる行が項目。各項目に根拠の区別。判断に効かせる項目に `[T#]` |
| `translation.md` | 列が「ID・由来・感性・判断」の表。ID は `T#` か `M#`。profile・context の `[T#]` と memories の `M#` のすべてに行がある |
| `journeys.md` | `### J# 目的` と、`- 入口:`・`- 期待する手数:`・`- 中断されやすい所:`・`- 戻り方:`・`- 判断:` の行（1 つ以上） |
| `moments.md` | `## 気持ちいい瞬間` の下に `### G# 場面`、`## 引っかかる瞬間` の下に `### F# 場面`。見出しの行に根拠の区別。それぞれに `- 心の声:` と `- 判断:` の行。`F` は 1 つ以上 |
| `memories.md` | `### M# 見出し` と、`- 今の判断:` の行（3〜5 個が目安） |
| `voice.md` | `## 思考発話サンプル` の下に `- 「…」` の行が 3 つ以上 |
| `research.md` | 列が「ID・主張・出典・取得日・種別」の表。取得日は `YYYY-MM-DD`、種別は決まった語（`references/research.md`） |
| `PERSONA.md` | 見出し「演じるときに読むファイル」「作業前の儀式」「出力の約束」「提出前の自己批評」 |

## §1 profile.md — 使っているもの

- 毎日・毎週使っているアプリ、サービス、端末を固有名詞で書く。慣れている操作（ショートカット、スワイプ、音声入力など）は、ここから導く
- 年齢・職業などの属性は土台として短く書く。属性から判断を導かない
- 判断に効かせる項目に `[T1]` … を付ける

| 悪い例 | 良い例 |
|---|---|
| IT リテラシーが低い | 仕事のチャットと乗換案内は毎日使うが、会社の業務システムは月 1 回しか開かない [T1] 〔出典: R3〕 |
| スマホに慣れている | 買い物はスマホのアプリで、カード番号は自動入力に任せている [T2] 〔推測: R5〕 |

## §2 context.md — 状況

UX の判断にいちばん効く層。見出しを次のように分け、各項目に根拠の区別を付ける。判断に効かせる項目に `[T#]` を付ける。

- `## 場所と姿勢`: どこで、立っているか座っているか、片手か両手か、画面の大きさ
- `## 頻度`: 毎日か、月に 1 回か、年に 1 回か。低頻度なら、毎回やり方を忘れている前提になる
- `## 急ぎ具合と中断`: 何をしながら使うか、どのくらい急いでいるか、何に中断されるか
- `## 状況の中での葛藤`: 急ぎたいが間違えたくない、のように、判断を揺らす対立

## §3 translation.md — 判断への変換

列は「ID・由来・感性・判断」で、作り手と同じ（`references/layers-maker.md` §2）。感性の欄には「期待・慣れ」を書く。

| ID | 由来 | 感性 | 判断 |
|---|---|---|---|
| T1 | 業務システムは月 1 回しか開かない | 前回のやり方を覚えていない。覚えていなくても進めたい | 各画面に次の 1 手を 1 つだけ示す; 入力欄の下に、何を入れるかの例を必ず置く |

反応の速さ、動きの長さ、読み込み中の見せ方のような時間の感覚も、ここに数値で書く（「押してから 0.1 秒以内に押した手応えを返す」など）。

## §4 journeys.md — 道のり

- 見出しは `### J1 <目的>`。1 つの目的ごとに、入口から目的を果たすまでを書く
- 各道のりに次の項目を書く: `- 入口:`（どこから始めるか）、`- 期待する手数:`（何手で終わってほしいか）、`- 中断されやすい所:`、`- 戻り方:`（中断から再開するとき、どこから始めたいか）、`- 判断:`（検証可能なルール）

## §5 moments.md — 気持ちいい瞬間と引っかかる瞬間

- `## 気持ちいい瞬間` の下に `### G1 <場面>`、`## 引っかかる瞬間` の下に `### F1 <場面>` を書く
- 各瞬間に `- 心の声:`（その場で思わず言うこと）と `- 判断:`（検証可能なルール）を書く
- 引っかかる瞬間は、調査で集めた当事者の不満から作る。出典の ID を見出しの行に添える
- 瞬間の判断には、その瞬間に固有のこと（その場の文言・表示・手数）を書く。translation.md と同じ判断を写さない。同じことになるなら、瞬間の側を残して translation.md の行を消すか、translation.md の側を一般的なルールにする

## §6 memories.md — 痛い記憶

- 3〜5 個。見出しは `### M1 <見出し>`。「いつ / 何があった / どう感じた / 今の判断」で書く
- 使い手の記憶は、失敗した操作・失ったデータ・やり直しになった経験から作る。「今の判断」は、そこから生まれた期待を検証可能なルールにしたもので、translation.md に同じ ID の行として写す

## §7 voice.md — 声

- `## 口調の特徴`: 語尾、口癖、使わない言葉
- `## 思考発話サンプル`: 3 つ以上。`- 「…」` の形で、操作しながら思ったことを口に出す形で書く。なぞる役では、エージェントがこれを手本にする
- `## 批評の言い方`: 専門用語を使わず、自分の状況の言葉で言う（「ここで電車が着いたら、どこまで保存されてる？」）

## §8 PERSONA.md — 入口

雛形（`assets/templates/user/PERSONA.md`）の見出しをすべて残す。

- 役割は「なぞる」と「批評する」
  - なぞる: 画面・プロトタイプ・操作の流れを、この人物として 1 手ずつ進み、各手で思考発話を書く。引っかかった手には引っかかりの ID（`F2` など）か、どれにも当たらなければ「ID なし」を添える
  - 批評する: 設計案を、ルール（`T`・`M`・`J`・`G`・`F`）に照らして指摘する
- 演じる側は、デザインの専門家として振る舞わない。専門用語で考えず、この人物の状況と言葉で判断する
